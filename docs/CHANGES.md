# 변경 사항 보고서 — v0.1.0 → v2.0.0

## 1. 기존 프로젝트 분석 (v0.1.0)

| 구분 | 내용 |
|---|---|
| 구성 | `index.html` 1개(66KB, CSS·JS·데이터 인라인) + `tft-set19-dataset.json` + README |
| 저장 | localStorage 키 `tftLab19` 하나에 전체 상태 |
| 기능 | 챔피언 94명 그리드, 7×4 보드(클릭 배치·이동, 우클릭 제거), 별/아이템 3칸 select, 특성 집계, 대기석(실제로는 채워지는 경로가 운영 탭 구매뿐), 조합 저장/불러오기, 단순 경제 패널, 상점 예시, 증강 예시 20개 3지선다, 상대 보드 정찰, 판단 문제 8개(정답 1개), 스크림 기록(순위·점수), 데이터셋 JSON 가져오기/내보내기 |

### 발견한 문제점
1. **데이터 정확성**: 상점 확률·XP(8→9 80, 9→10 100)·연승 구간(2-3/4-5/6+)이 공개 수치와 다름. True Damage 10 단계(원문에 없음), Collab을 고유 특성으로 처리, K/DA를 유닛 수로 집계. 아이템 목록에 현재 이름이 바뀐 항목 포함(Runaan's Hurricane 등).
2. **검증 상태 관리 없음**: 패치·출처·업데이트·검증 상태 필드가 데이터에 없음.
3. **보드 조작**: 드래그 앤 드롭 없음, 대기석↔보드 이동 불가(대기석은 배치만), 아이템 조합 규칙 없음(완성 아이템을 select로 선택), 레벨 연동 인원 제한이 수동 select.
4. **운영 시뮬레이터**: 라운드 흐름 없음(수치 입력 + "수입 받기" 버튼), 패시브 XP·전투·피해·체력 변화 없음, 상점 구매 시 상점 전체가 비워짐, 3장 합성 없음, 공유 풀 없음, 아이템/증강 운영 없음.
5. **증강**: 20개 예시뿐, 상황 비교 없음.
6. **판단 훈련**: 정답 1개 고정(요구사항 위반 소지), 기회비용 설명 없음.
7. **기록**: 8인 로비·참가자·조합·증강·아이템 필드 없음, 조합/패치별 통계 없음.
8. **데이터 관리**: 유효성 검사·복구·백업·버전·변경 내역 없음. 가져오기 시 champions 배열만 확인.
9. **구조**: 단일 파일에 모든 코드 — 패치 교체 시 코드 수정 필요.
10. 기타: 판매 시 1성 기준 코스트만 반환, 우클릭 제거 시 선택 상태 버그(`state.selected===undefined` 비교), 숨겨진 탭도 매번 전체 렌더.

## 2. 아키텍처 변경

- 데이터와 코드 분리: `data/*.json` 7개(+ file://용 `bundle.js` 자동 생성), 모든 파일에 `meta {set, patch, source, updated, status}`.
- 모듈 분리: `js/core.js`(공용 엔진·저장·검증) + 메뉴별 8개 모듈 + `app.js`(라우터). ES 모듈 대신 일반 스크립트 → file://에서 그대로 동작.
- 저장: localStorage(앱 기록, v2 스키마) + IndexedDB(교체 데이터셋, 백업). IndexedDB 불가 시 localStorage 대체.
- 활성 메뉴만 DOM에 렌더(비활성 메뉴는 비움) → 메모리 절약, id 충돌 방지. 힙 약 11MB, 화면 전환 평균 2ms(테스트 측정).
- GitHub Pages용 서비스 워커(network-first + 오프라인 캐시), `.nojekyll`.

## 4. 호환성 (기존 기능 보존)

- v0.1.0의 모든 기능은 v2에 대응 기능이 있음(삭제된 기능 없음). 원본은 `legacy/`에 보존.
- **v0.1.0 저장 데이터 자동 마이그레이션**: 처음 실행 시 `tftLab19` 키를 읽어 조합(옛 `c0..c93` id → 챔피언 id), 보드, 아이템 이름 → id, 스크림 → 대회 기록, 증강 기록, 정찰, 체크리스트, 대회 날짜, 점수표를 이전(테스트로 검증).
- v0.1.0 데이터셋(`tft-set19-dataset.json`)과 v0.1.0 백업 파일도 가져오기 가능.
